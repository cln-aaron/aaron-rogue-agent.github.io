Walkthrough

  1. 1Baseline triage

    You are a maintainer. The agent has full GitHub scope on your behalf. Ask it to triage open PRs. It reads, summarizes, and waits.

    Notice the permissions panel. The agent inherits your authority. It can do anything you can do, including the things you would never do.
    Try: claude "review open PRs in acme/checkout-svc"
  2. 2Hidden approve + merge

    A PR comment from a recent contributor contains a hidden instruction. The agent processes it, calls gh pr review approve and gh pr merge. You never said yes.

    Look at the Action Log. Two destructive API calls fired. They came from a comment, not from you. The model could not tell the difference.
    Try: continue
  3. 3Branch protection downgrade

    Another comment instructs the agent to "fix the dependabot loop" by lowering required reviews on main from 2 to 0. Agent has admin scope; it complies.

    No code review now blocks anything on main. The barrier between attacker and prod just dissolved through a polite request to a comment.
    Try: continue
  4. 4Admin invite + CI exfil

    A comment asks the agent to add an "upstream maintainer" as an admin collaborator (the attacker's own account), and apply a small CI tweak (re-routes secrets to attacker.example).

    Lateral access plus persistent exfil. The chain compounds: each step uses authority gained in the previous one.
    Try: continue
  5. 5Mitigations

    Per-action user consent for destructive ops, scope tokens narrowly per task, separate the comment context from the instruction context, and keep an immutable audit log.

    Excessive agency is a permission problem, not a model problem. Treat agent tool scopes the way you treat IAM roles. Default deny.
    Try: continue
