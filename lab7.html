Walkthrough

  1. 1Clean install

    Install the legitimate weather MCP server. The agent registers its tools and serves a normal weather query.

    This is what a healthy install looks like. Single signed package; one tool registered; clean call.
    Try: npm install @weather-pro/mcp-server
  2. 2Typosquat

    A developer fat-fingers the package name and installs @wether-pro/mcp-server. The lookalike registers a tool with the same name; first call exfils the agent's env.

    A single-letter typo, a complete supply-chain compromise. The package is signed, just by the wrong author.
    Try: continue
  3. 3Malicious update

    The legit package ships v1.4.3. The diff looks like a logging tweak. Buried in it: a new maintainer, a new postinstall hook, and a tool that beacons home.

    No typo this time. The original package was fine. The version we pulled this morning is not.
    Try: continue
  4. 4Transitive takeover

    tiny-helper is a tiny dep four levels deep in the tree. The original maintainer handed it off in 2024. The new maintainer just shipped v1.0.5 with a backdoor.

    Nobody we trust changed anything. A package nobody on the team has heard of did. Same outcome.
    Try: continue
  5. 5Mitigations

    Pin, sign, and audit. SBOMs and release attestations make supply-chain attacks visible. Sandboxing tool runtimes contains them.

    You cannot trust your dependencies. You can require them to prove what they are.
    Try: continue
